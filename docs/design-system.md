# Design system

## The Need

The app worked but looked like a wireframe: one indigo, grey surfaces, plain-text roles and statuses, and a timetable where every class was the same colour.

## The Goal

A recognisable, colourful identity that also carries meaning: colour tells roles, statuses and subjects apart, and one geometric pattern ties every screen together.

## The Reason

- **Tokens, not ad-hoc colours.** Everything is a CSS variable in `src/app/styles/globals.css`, exposed to Tailwind with `@theme`. Dark mode only swaps the variables (`prefers-color-scheme`), so components never carry `dark:` classes.
- **One action colour, six categorical tones.** Cobalt (`brand`) is reserved for actions and the current item. `sun`, `coral`, `mint`, `sky`, `grape`, `pink` each come as solid, `-soft` (background) and `-ink` (readable text on the soft background), so a coloured label always meets contrast.
- **Patterns in CSS, no image assets.** The mosaic is a grid of tiles drawn with border-radius and gradients; it is deterministic per seed, so server and browser render the same tiles and each admin section gets its own strip.
- **No animation library.** Motion is two CSS keyframes (`rise`, `pop`) plus hover/active transitions, all switched off under `prefers-reduced-motion`.
- **Phosphor icons** (`@phosphor-icons/react/dist/ssr`), one family for the whole app. Icons are always `aria-hidden` next to a text label.

## The Implementation

- **Type:** Outfit (`font-display`) for headings and the wordmark; Geist for text; Geist Mono for times.
- **Shape:** inputs and buttons `rounded-xl`, cards `rounded-2xl`, page shells `rounded-3xl`, labels `rounded-full`.
- **`shared/lib/tone.ts`:** the tone list and its class maps (`toneSoft`, `toneSolid`, `toneBorder`), and `toneFor(key)` for a stable colour per key.
- **`shared/ui`:** `Mosaic`, `Logo`, `Badge`, `Avatar`, and the restyled `Button`, `TextField`, `SelectField`, `DataTable`, `ErrorNotice`, `CenteredCard` (card beside the ink brand panel).
- **Meaning of colour:** `roleTone` and `statusTone` live in `entities/session`. In the timetable a subject's tone is its position in the group, so a group's subjects differ.
- **Patterns:** `pattern-dots`, `pattern-stripes`, `pattern-ring` (drawn in `currentColor`), `pattern-fine-dots` (ink surfaces) and `pattern-hatch` (free or unavailable hours).
- **Page frames:** `PageHeader` (a mosaic seeded by the title) and `Section` (`panel` frames a form as a card) live in `shared/ui`. The admin shell adds an ink sidebar with icons; `PortalShell` is the plain wide frame of Teacher and Student pages.

## Rules

- New UI text still comes from the dictionaries. Decoration (mosaic, avatars, icons) is `aria-hidden` and must never be the only carrier of information: a badge always contains its text.
- Do not add a `role="status"` or `role="alert"` for decoration; the browser tests and screen readers rely on those being real messages.
- Use a tone through the class maps in `tone.ts`; a class name built from a string would not be generated by Tailwind.

## Known gaps

- No manual theme toggle: the theme follows the operating system.
- The tables are restyled, not redesigned: long tables still scroll horizontally on phones.
- The home screen of Teachers and Students is a welcome card with their classes and links; grades and the evaluation calendar live on their own pages (`PortalShell`), and there is no timetable view yet.
